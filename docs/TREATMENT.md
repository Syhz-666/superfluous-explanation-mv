# 《多余的解释》MV · 处理方案

> 参考 pdoom-video 的 TREATMENT.md 结构：概念 → 风格圣经 → 分镜表 → 技术约定。
> 分镜表见 `STORYBOARD.md`。

## 概念

她解释了一整首歌，但**没有一句被听进去**。

全片只有两个"人"：**她**，和**始终看不清的对方**。对方以三种形态出现——
通话时的手机、站在侧后方的虚化剪影、以及桥段里那两个并肩的背影。
**从头到尾没有一张正脸**，只有"在场"。

**「妹妹」用缩小版的她自己来演**。她说「她只是我的妹妹」的时候，
妹妹就站在旁边 —— 画面本身构成反讽：越是解释，越显得此地无银。

全片唯一的暖色是一条紫色围巾：第 9 句在橱窗里出现，桥段成为主角，
之后褪回冷蓝，尾奏完全消失。

**反转在桥段**：前面三十多句都是她的辩解，桥段里「要加班的你却出现在这里」
一句把整个前提推翻 —— 她解释了一整首歌，而对方根本不在听。

## 风格圣经

### 调性 · 五条

1. **一切运动落在拍上**，用强缓动收尾，不做匀速漂移
2. **克制优于炫技** —— 宁可少一个镜头，不要多一个特效
3. **冷是常态，暖是例外** —— 暖色出场的次数，全片一只手数得过来
4. **第二个人永远看不清脸** —— 只以虚化剪影、缩小版、并肩背影出现
5. **画面服从歌词** —— 歌词是主角，背景是配角

### 禁用清单

- ❌ 霓虹赛博朋克（紫青撞色、扫描线、故障艺术）
- ❌ 粒子爆炸 / 光效堆砌 / 泛光过曝
- ❌ 镜头抖动（手持感）
- ❌ 花哨转场（叠化、翻转、擦除、缩放推移）
- ❌ 出现第二张脸
- ❌ 画面里出现任何可读的文字（除歌词本身）

### 调色板

| 名称 | 色值 | 用途 |
|---|---|---|
| 夜底 | `#05091C` | 最暗处 |
| 深空 | `#0A1233` | 天空下半 |
| 城影 | `#111A3E` | 楼群剪影 |
| 天光 | `#1E2C63` | 天空上半 |
| 冷光 | `#4D6BFE` | DeepSeek 蓝，角色与光晕 |
| 亮蓝 | `#8FA8FF` | 雪、边缘光、UI |
| **紫围巾** | **`#8E6BC8`** | **全片唯一暖色** |
| 暖窗 | `#FFC478` | 橱窗与窗灯 |

> **一个稀有的重音，只属于一个时刻。**
> 紫围巾在第 9 句（48.8s）第一次出现，桥段（166.8–182.3s）成为画面主角，
> 之后逐步褪成冷蓝，尾奏完全消失。

**辉光上限**：任何高光的亮度不超过 78%，保证歌词文字始终清晰可读。

### 字体

| 用途 | 字体 | 规格 |
|---|---|---|
| 歌词 | 微软雅黑 / PingFang SC | 500 字重，字距 4，白色带冷光晕 |
| 时间码（调试） | 等宽 | 极小、低透明度，成片删除 |

### 歌词规则

- 位置固定在**画面下三分之一**，水平居中
- 出入场：淡入 + 上浮 14px，8 帧
- 换句时交叉淡入淡出，**不允许两句同时清晰可读**
- 落幕时间：下一句开始前 8 帧
- **升级方向**：目前是整句出现，目标是**词级逐字点亮**（词级时间码已具备）

### 母题（六个）

1. **紫围巾** —— 关系的物证。出现 → 成为主角 → 褪色 → 消失
2. **虚化剪影** —— 「你」。站在她侧后方，压到 0.76 高、明显虚化、不透明度 0.8。
   **退远是关键** —— 做成和她一样大一样实就是一块抢戏的黑斑（实测过）
3. **缩小版她自己** —— 「妹妹」。0.62–0.72 倍高，略压暗。副歌里就站在她旁边
4. **两个并肩的背影** —— 全片只在两处出现：主歌一结尾（模糊）、桥段（清晰）。
   桥段是终局
5. **雪** —— 时间流逝。密度随情绪：主歌密，副歌稀，尾奏停
6. **城市窗灯** —— 别人的生活。一盏盏亮着，尾奏里一盏盏灭

## 技术约定

| 项 | 约定 |
|---|---|
| 帧率 / 分辨率 | 30fps / 1920×1080（尾奏可选 4K 真渲） |
| 逐帧确定性 | 每帧是歌曲时间的纯函数，无 `Math.random`、无 `useEffect` |
| 硬切时机 | **落在小节的强拍上**，不落在任意帧 |
| 律动 | 升余弦脉冲（峰落在拍上，两拍交界处导数为零）+ 慢速呼吸 + 微摆。**走缩放不走位移** |
| **运动模糊** | **时间超采样**：同一帧内用 `Freeze` 把场景在最近 3 帧各渲染一次，按 1、1/2、1/3 的透明度叠加（数学上等价于等权平均）。**只作用于场景层，不作用于歌词** —— 像真实摄影机，模糊是拍出来的，字幕是后期叠的 |
| 歌词同步 | 时间码来自 `assets/lyrics.lrc`（人工校对），已用 demucs 分离人声 + faster-whisper 全局 DP 比对**交叉验证**（两者与真实起音点贴合度等价，中位偏差同为 167ms） |
| 拍点数据 | librosa 分析，已在纯人声轨上验证 |

### 渲染开销实测

| 配置 | 400 帧耗时 | 整曲预估 |
|---|---|---|
| 无运动模糊 | 16.6 s | ~7 分钟 |
| 3 子帧运动模糊 | 30 s | **~10 分钟** |
| 硬件编码（`h264_nvenc`） | 16.6 s | 无提升（差 2%） |
| CPU / GPU 占用 | **CPU 84% / GPU 0%** | 瓶颈在 CPU，加 GPU 没用 |

> 试过两条"优化"路线，**都失败了，已还原**：
> ① 把城市 ~110 个矩形合并成 path（节点减到 5）→ 反而慢 25%，大 path 光栅化更贵
> ② 给雪加 `willChange: transform` 提升合成层 → 慢 25%，建层开销超过省下的布局开销
> 两个文件里都留了注释，避免以后重走。

## 数据来源

```
assets/lyrics.lrc          歌词文本（人工校对版，原样保存）
analysis/vocals.wav        demucs 分离的纯人声轨
analysis/words.json        faster-whisper 词级时间码
src/lyricTiming.ts         最终时间码（LRC 文本 + 音频时间，逐行择优）
analysis.json              BPM 83.35 / 381 拍 / 段落
```

**时间码不依赖任何网上流传的 LRC 版本** —— 文本用人工校对的，
时间用从本项目音频算出来的，逐行挑更贴近真实人声起音的那个。
